## Disposition vocabulary and mapping

Each entry uses the ARCH-R03.2 vocabulary in the column "Disposition". The column "Design term" keeps the term of the design's Component classification. The mapping is:

| Design term | ARCH-R03.2 disposition |
| --- | --- |
| REUSE AS IS | reuse as is |
| REUSE WITH ADAPTATION | adapt |
| DEPRECATE AFTER MIGRATION | retire; replace where the design names a canonical replacement |
| EXTEND | not used here: the design gives EXTEND only to canonical DATA components (tables, `repositories.js`, `app.js` and others), never to a Standalone_Implementation artifact |
| REQUIRES OWNER DECISION | not used here: those design rows are policies, not artifacts (see "Not inventory entries") |

Meaning of the four dispositions in this document:

- reuse as is: kept unchanged and used by the canonical code or tests.
- adapt: the logic or the test is ported into Canonical_DATA (or, for the client, changed in place at DB-6E) with the changes the requirements force.
- replace: nothing is ported. A canonical artifact written from the requirements takes the place of the standalone one.
- retire: nothing is ported and no canonical artifact takes its place, or the canonical schema supersedes it. The original stays unchanged in the tree until T-7-05 adds deprecation markers.

Where the design has no row for an artifact, or its row is ambiguous, the entry says so in its reason.
